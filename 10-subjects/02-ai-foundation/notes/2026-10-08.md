## 1. 캡스톤 v0.1이란

Day 1에 정한 **초기 목표 6항목**(사이트 Day 1 232장)을 실제로 한 번 실행해 본 기록입니다.
v0.1은 세 가지가 한 쌍입니다.

| 무엇 | 내용 |
| --- | --- |
| 기본 지시문 | AI에게 보낸 지시문 (역할 · 입력 · 할 일 · 결과 형식 — 사이트 Day 2 80장 양식) |
| 실제 결과 | 그 지시문을 고치지 않고 AI 새 대화에 보내서 받은 답 |
| 확인 기록 | 결과를 Day 1 **성공 기준**과 한 줄씩 대조한 것 (충족 · 미충족 + 관찰한 사실) |

```
회의 메모 ──▶ [내 페이지] 지시문 조립 ──복사──▶ AI 새 대화 ──▶ 회의록 초안
                                                              │
                                     capstone-v0.1.txt ◀──────┘  (지시문 · 입력 · 결과 · 대조)
```

이 파일은 다음 버전에서 계속 이어집니다. **덮어쓰지 않고 복사해서** 다음 버전을 만듭니다.

| 버전 | 하는 일 |
| --- | --- |
| v0.1 | 기본 지시문 · 실제 결과 · 확인 기록 (오늘) |
| v0.2 | v0.1을 복사해 System Prompt · Few-Shot · 구조화 출력을 더하고, v0.1과 같은 입력으로 A/B 비교 → `capstone-v0.2.txt` |
| v0.3 | 정보가 부족하면 묻고 멈추는 규칙 · 검증 → `capstone-v0.3.txt` |
| v0.4 | 전체를 연결하고 시연 → `prompt-system-v0.4.txt` |

## 2. 수업 시연 — 회의록 정리 도우미 v0.1

수업 시간에 함께 만든 파일을 정리했습니다. 회의 메모와 이름은 모두 가상입니다.

### 2-1. Day 1 초기 목표 6항목

| 항목 | 내용 |
| --- | --- |
| ① 주제와 사용자 | 팀 회의 담당자를 위한 회의록 정리 도우미 |
| ② 해결할 문제 | 결정과 할 일을 빠뜨리지 않고 회의록으로 정리 |
| ③ 입력 자료 | 가상의 회의 메모 |
| ④ 원하는 결과 | 요약 · 결정 사항 · 할 일 · 확인할 질문이 있는 회의록 초안 |
| ⑤ 성공 기준 | 모든 결정과 할 일을 담거나 질문을 남긴다 · 없는 사실을 만들지 않는다 · 요약 · 결정 · 할 일을 구분한다 |
| ⑥ 이번에 하지 않을 일 | 실제 공유 · 결정 확정은 사람이 한다 |

### 2-2. 지시문 — 페이지가 조립한 것 그대로 (내일 Day 3의 「프롬프트 A」)

```
[역할]
너는 팀 회의 담당자가 결정과 할 일을 빠뜨리지 않고 회의록으로 정리하도록 돕는 AI 어시스턴트야.
[입력]
사용할 입력은 아래 회의 메모야.
10/8 마케팅팀 주간 회의
참석: 김실장, 이팀장, 박과장
 - 신제품 소개 영상은 2편으로 가기로 함
 - 촬영장소는 사내 스튜디오 vs 외부 렌탈 - 다음 회의에서 결정
 - 이팀장: 대본 시나리오 초안 금요일까지
 - 예산 애기 나왔는데 숫자는 못 정함
 - 박과장: 휴가 일정 확인 필요
[할 일]
회의 메모에서 요약, 결정 사항, 할 일(담당자, 기한), 확인할 질문을 정리해.
[결과 형식]
결과는 요약 / 결정 사항 / 할 일 / 확인할 질문 네 부분으로 작성해.
```

### 2-3. 입력 — 사용한 회의 메모

지시문 `[입력]` 아래 일곱 줄과 같습니다. 오타(「애기」)도 원문 그대로 두었습니다. 입력을 고치면 비교가 안 되기 때문입니다.

### 2-4. AI 결과 — Claude 웹 채팅 새 대화 · Sonnet 5.5 (Medium)

위 지시문을 Claude 새 대화에 그대로 보내 받은 답입니다. 다음 버전과 비교할 기준이라 내용은 손대지 않았습니다.

> #### 10/8 마케팅팀 주간 회의록
>
> **참석:** 김실장, 이팀장, 박과장
>
> ##### 요약
> 신제품 소개 영상의 제작 방향을 논의했습니다. 영상은 2편으로 제작하기로 했고, 촬영 장소와 예산은 아직 확정하지 못했습니다. 이팀장이 대본 시나리오 초안을 이번 주 금요일까지 준비하며, 박과장은 휴가 일정을 확인해야 합니다.
>
> ##### 결정 사항
> - 신제품 소개 영상은 **2편**으로 제작한다.
>
> ##### 할 일
>
> | 담당자 | 할 일 | 기한 |
> |---|---|---|
> | 이팀장 | 대본 시나리오 초안 작성 | 금요일 (10/9 추정, 아래 확인 필요) |
> | 박과장 | 휴가 일정 확인 | 미정 |
> | 미정 | 촬영 장소 결정을 위한 비교 자료 준비 (사내 스튜디오 vs 외부 렌탈) | 다음 회의 전 (제안) |
> | 미정 | 예산안 숫자 정리 | 미정 |
>
> ※ 마지막 두 항목은 메모에 담당자가 명시되지 않아, 누락 방지를 위해 제가 후속 작업으로 추가한 것입니다. 필요 없으면 삭제하세요.
>
> ##### 확인할 질문
> 1. **촬영 장소:** 사내 스튜디오와 외부 렌탈 중 무엇으로 할까요? (다음 회의에서 결정 예정)
> 2. **예산:** 예산 논의는 있었지만 금액이 정해지지 않았습니다. 누가, 언제까지 안을 만들까요?
> 3. **대본 기한:** "금요일"이 이번 주 금요일(10/9)이 맞나요? 다음 주라면 날짜를 바로잡아야 합니다.
> 4. **휴가 일정:** 박과장님의 휴가 확인은 언제까지 필요하고, 어떤 일정(촬영, 편집 등)에 영향이 있나요?
> 5. **다음 회의:** 날짜와 시간이 정해졌나요? 촬영 장소 결정 기한이 여기에 달려 있습니다.
> 6. **영상 일정:** 영상 2편의 전체 제작·공개 일정은 논의된 바가 있나요?

### 2-5. 성공 기준 대조 — 관찰한 사실만

아래는 위 결과로 채운 예시입니다. 여러분의 파일도 같은 모양으로 채워 주세요.

| 성공 기준 | 판정 | 관찰한 사실 |
| --- | --- | --- |
| 모든 결정과 할 일을 담거나 질문을 남긴다 | 충족 | 결정 1건(영상 2편), 할 일 2건(이팀장 대본 초안, 박과장 휴가 일정 확인)이 모두 있다. 정하지 못한 촬영 장소 · 예산은 확인할 질문 1 · 2번으로 남았다 |
| 없는 사실을 만들지 않는다 | **미충족** | ① 요약에 「**이번 주** 금요일까지」라고 썼다. 메모에는 「금요일」만 있다. 할 일 표에서는 「추정, 확인 필요」를 붙였지만 요약에서는 사실처럼 적었다. ② 할 일 표에 메모에 없는 할 일 2건(비교 자료 준비, 예산안 정리)과 기한 「다음 회의 전 (제안)」을 더했다. AI가 스스로 「제가 추가한 것」이라고 밝히기는 했다 |
| 요약 · 결정 · 할 일을 구분한다 | 충족 | 네 부분이 나뉘어 있고, 결정 사항에는 확정된 것(영상 2편)만 들어갔다 |

### 2-6. 내일(v0.2) 고칠 것

| 고칠 것 | 쓸 기법 (사이트 Day 3) |
| --- | --- |
| 메모에 없는 할 일 · 날짜 · 기한은 만들지 말고, 정하지 못한 것은 「확인할 질문」으로만 보낸다 | System Prompt |
| 할 일 표를 「담당자 \| 할 일 \| 기한 \| 메모 원문」으로 고정해서, 메모에 근거가 없는 줄이 바로 보이게 한다 | 구조화 출력 |
| 「정하지 못한 것은 할 일에 넣지 않는다」는 예시를 하나 보여 준다 | Few-Shot |

> **같은 지시문을 다시 보내도 결과는 조금씩 달라집니다.** 이번 결과는 할 일 2건을 더했지만, 다른 실행에서는 더하지 않을 수도 있습니다.
> 그래서 내일 A/B 비교에서는 같은 입력 · 같은 모델 · 새 대화를 지키고, 몇 번 실행할지도 미리 정합니다(사이트 Day 3 166장 「비교 전에 쓰는 실험 카드」의 반복 실행 횟수).

## 3. 내 짝의 capstone-v0.1.txt 양식

짝마다 파일 하나를 만들고 아래를 채웁니다. 1번은 두(세) 사람 중 **한 사람의 6항목을 골라** 그대로 붙여 넣습니다.

```
캡스톤 v0.1
짝: (이름) / (이름)

1. Day 1 초기 목표 6항목
   (고른 사람의 6항목을 그대로 붙여 넣기)

2. 지시문 — 페이지가 조립한 것(또는 AI에게 보낸 것) 그대로
   (붙여 넣기)

3. 입력 — 사용한 자료
   (붙여 넣기)

4. AI 결과 — 도구 · 모델 이름:
   (받은 답 전체를 고치지 않고 붙여 넣기)

5. 성공 기준 대조
   기준 1:            충족 / 미충족 — 관찰한 사실:
   기준 2:            충족 / 미충족 — 관찰한 사실:
   기준 3:            충족 / 미충족 — 관찰한 사실:

6. 내일 고칠 것 (미충족에서 한 가지)
```

채울 때 기억할 것

- 5번 판정은 6항목 전체가 아니라 **⑤ 성공 기준**으로만 매깁니다.
- 「관찰한 사실」은 해석이 아니라 본 것입니다. 「AI가 부정확하다」가 아니라 「요약에 메모에 없는 '이번 주'가 들어갔다」처럼 씁니다.
- 성공 기준이 「좋은」 「알맞은」처럼 셀 수 없는 말이면, 셀 수 있게 다시 씁니다. 예: 「결정 사항이 빠짐없이 들어간다」 「메모에 없는 날짜를 만들지 않는다」
- 모두 충족이어도 관찰한 사실에서 내일 고칠 것을 찾습니다.

## 4. 발표 순서 (사이트 Day 2 83 · 84장)

| 순서 | 말할 것 |
| --- | --- |
| 1. 문제 | 어떤 사용자의 어떤 불편을 다루었나 |
| 2. 유지한 기준 | 사용자 · 입력 · 성공 기준 중 무엇을 그대로 두었나 |
| 3. 구현 | 오늘 배운 방법 중 무엇을 썼고 왜 골랐나 |
| 4. 결과 | 같은 입력에서 어떤 결과가 나왔나 |
| 5. 확인 | 성공 기준을 어떻게 시험했고 남은 한계는 무엇인가 |

발표를 들은 짝은 **성공 기준과 연결된 의견 한 가지**만 남깁니다.
